# Yogurt AI development plan

## Product outcome

Turn Yogurt AI into a source-grounded, non-linear thinking canvas where Codex can grow cards, relations, images, and live HTML charts beside the user's material; understand selected visual annotations; apply only local edits; explain them; and undo the last agent operation safely.

## MVP boundary

The MVP adds four capabilities and reuses Cowart for everything else:

1. **Material cards** — attach a project-local copy of a source file to an editable canvas card with a title, summary, excerpt, and provenance metadata.
2. **Compact canvas context** — expose selected or page-level cards, shapes, images, annotations, and relations without sending the raw tldraw store to the model.
3. **Atomic local operations** — preview and then apply batches of card, relation, move, resize, and guarded-delete operations against an optimistic revision.
4. **Annotation review loop** — export selected content plus nearby marks, send it to Codex, apply the resulting local operation batch, explain the interpretation, and retain an undo snapshot.

Existing Cowart image generation, HTML drafts, Slides, page storage, asset loading, selection persistence, and live refresh remain the single implementations of those concerns.

## Non-goals for the MVP

- No second canvas renderer, storage format, chat system, or document database.
- No autonomous whole-board rewrite.
- No silent deletion of images, imported materials, or user-authored shapes.
- No bundled OCR, PDF, DOCX, or embedding stack; Codex reads supported workspace files and stores source-grounded excerpts on cards.
- No background agent or automatic mutation without a user request.
- No graph database or vector index until real usage proves the compact context insufficient.

## Safety and anti-drift invariants

- Every agent mutation is a typed operation, never a hand-written snapshot replacement.
- Apply requires the revision returned by the latest context or preview call.
- A batch is all-or-nothing and validated before persistence.
- User-authored content edits require an explicit `allowUserAuthoredEdits` flag.
- Deletes are limited to shapes generated by the thinking agent.
- Each applied batch stores its reason, explanation, before snapshot, and resulting revision.
- Undo succeeds only when the current canvas still matches that batch's resulting revision.
- Source path, source excerpt, and AI synthesis remain distinguishable in card metadata.

## Delivery sequence

1. Add pure context and operation modules with unit tests.
2. Register thin MCP tools that delegate to those modules.
3. Add a generic selected-region annotation action to the existing Cowart overlay.
4. Add one concise thinking-agent skill that enforces inspect → preview → apply → explain.
5. Rename the fork so it installs beside upstream Cowart, then run build, probes, validation, and packaged smoke tests.

## Acceptance scenarios

1. Import two source documents as material cards, ask Codex to create three evidence-backed idea cards and relations, and see them appear without moving the source cards.
2. Select a cluster, circle two cards, write “merge these”, submit the annotations, and receive one previewed local edit with an explanation.
3. Ask for a comparison chart and receive an editable HTML draft beside the relevant cards using Cowart's existing HTML path.
4. Change the canvas after an agent batch, then verify stale undo is refused instead of overwriting newer work.
5. Run all checks with no duplicate canvas, persistence, messaging, or image-generation implementation.
